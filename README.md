# Dobot Bidirectional Obstacle Avoidance Safety Demo

This project demonstrates the bidirectional obstacle avoidance and safety perception capability of the Dobot quadruped robot based on front and rear depth cameras. The program reads front and rear depth images through DDS, calculates obstacle distances, and publishes depth images, point clouds, distance markers, and safety states in ROS 2 and RViz2.

Robot motion is controlled by the **remote controller**.

## Features

- Subscribe to the forward depth DDS topic: `rt/camera/camera2/image_depth`
- Subscribe to the rear depth DDS topic: `rt/camera/camera3/image_depth`
- Calculate obstacle distances within the front and rear ROI areas
- Publish ROS 2 depth images, point clouds, distances, states, and RViz Markers
- Enable the quadruped robot's built-in obstacle avoidance at startup: `set_obstacle_avoidance(True)`
- Display front and rear depth images, point clouds, and distance labels in RViz2
- When the front or rear distance enters the danger threshold, the quadruped robot automatically triggers an emergency stop and outputs the safety state in the console and ROS 2 topics

## System Architecture

```text
Forward depth camera DDS: rt/camera/camera2/image_depth
Rear depth camera DDS: rt/camera/camera3/image_depth
        │
        ▼
depth_bridge_node
        ├─ Convert depth images to ROS 2 Image
        ├─ Generate PointCloud2 from depth images
        ├─ ROI distance calculation
        └─ RViz Marker publishing
        │
        ▼
safety_guard_node
        ├─ Enable the quadruped robot's built-in obstacle avoidance
        ├─ Subscribe to front and rear obstacle distances
        ├─ Maintain the safety state machine
        └─ Publish safety states and events
```

## Safety States

| State | Meaning |
| --- | --- |
| `SAFE` | Both front and rear distances meet the safe distance requirement |
| `FRONT_DANGER` | The front distance has entered the danger threshold |
| `BACK_DANGER` | The rear distance has entered the danger threshold |
| `BOTH_DANGER` | Both front and rear distances have entered the danger threshold |
| `RECOVERING` | The obstacle has been removed and the system is waiting for the recovery stabilization time |
| `SENSOR_STALE` | Depth data has timed out or has not been received yet |

## Install Dependencies

Install system dependencies:

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip python3-colcon-common-extensions
```

Create and activate a virtual environment:

```bash
cd ~/dobot_safety_guard_demo
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip setuptools wheel
```

It is recommended to perform subsequent installation, build, and startup steps in this virtual environment to ensure that `python` can find the ROS 2 packages, Dobot gRPC SDK, and DDS Python dependencies.

Install ROS 2 Python build dependencies:

```bash
python -m pip install empy==3.3.4 catkin_pkg lark requests pyyaml
```

Install the Dobot high-level gRPC SDK:

```bash
cd ~/dobot_safety_guard_demo/dobot_quad_sdk-main/high_level/python
python -m pip install -e .
```

Verify the high-level SDK. Any output indicates that the installation was successful:

```bash
python -c "import dobot_quad; print(dobot_quad.__file__)"
```

Install the DDS middleware and Python dependencies:

```bash
cd ~/dobot_safety_guard_demo/dobot_quad_sdk-main/dist
sudo dpkg -i dds-middleware-with-thirdparty*.deb
export CYCLONEDDS_HOME="/usr/local/"
python -m pip install dds_middleware_python-*.whl
python -m pip install cyclonedds opencv-python numpy pyyaml
```

Verify the DDS dependencies:

```bash
python -c "import dds_middleware_python; print('dds ok')"
python -c "import cyclonedds; print('cyclonedds ok')"
```

## Configuration Description

Configuration file:

```text
src/dobot_safety_guard_demo/config/safety_guard_config.yaml
```

Key parameters:

```yaml
robot:
  grpc_addr: "192.168.5.2:50051"
  enable_builtin_obstacle_avoidance: true

dds:
  config_file: "dobot_quad_sdk-main/low_level/python/config/dds_config.yaml"
  domain_id: 0
  front_depth_topic: "rt/camera/camera2/image_depth"
  back_depth_topic: "rt/camera/camera3/image_depth"

safety:
  front_danger_distance_m: 0.50
  front_recover_distance_m: 0.70
  back_danger_distance_m: 0.50
  back_recover_distance_m: 0.70
  recover_stable_seconds: 2.0
  stale_timeout_seconds: 3.0
  distance_publish_period_seconds: 0.05
  distance_sample_step: 2

visualization:
  pointcloud:
    use_roi_only: true
    sample_step: 4
    max_points: 12000
    publish_period_seconds: 0.2
  depth_image:
    publish_period_seconds: 0.1
```

Threshold descriptions:

- `front_danger_distance_m`: front danger distance, default `0.50m`.
- `front_recover_distance_m`: front recovery distance, default `0.70m`.
- `back_danger_distance_m`: rear danger distance, default `0.50m`.
- `back_recover_distance_m`: rear recovery distance, default `0.70m`.
- `recover_stable_seconds`: time that must remain stable before recovering from danger to safe.
- `stale_timeout_seconds`: depth data timeout.
- `distance_publish_period_seconds`: safety distance processing period, default `0.05s`, or approximately 20 Hz per side.
- `distance_sample_step`: ROI distance calculation sampling step, default one sample every 2 pixels.
- `pointcloud.use_roi_only`: publish only the obstacle avoidance ROI point cloud to keep the obstacle area clear and reduce RViz rendering load.
- `pointcloud.sample_step`: point cloud sampling step. Smaller values produce denser point clouds.
- `pointcloud.publish_period_seconds`: point cloud publishing period, default approximately 5 Hz per side.
- `depth_image.publish_period_seconds`: depth image publishing period, default approximately 10 Hz.

## Startup

```bash
cd ~/dobot_safety_guard_demo
source .venv/bin/activate
source /opt/ros/humble/setup.bash
source install/setup.bash
export CYCLONEDDS_URI=file:///home/dobot/dobot_safety_guard_demo/dobot_quad_sdk-main/cyclonedds.xml
ros2 launch dobot_safety_guard_demo safety_guard.launch.py
```

If the previous run exited abnormally, clean up old processes before startup:

```bash
pkill -f dobot_safety_guard_demo
pkill -f depth_bridge_node
pkill -f safety_guard_node
pkill -f rviz2
```

After startup, the launch includes:

- `depth_bridge_node`: subscribes to DDS depth images and publishes ROS 2 images, point clouds, distances, and Markers.
- `safety_guard_node`: enables built-in obstacle avoidance and publishes safety states and events.
- `rviz2`: displays depth images, point clouds, and obstacle distances.
- Static TF: provides the `safety_guard_base`, `front_depth_camera`, and `back_depth_camera` coordinate frames.

Example normal logs:

```text
Forward depth DDS topic: rt/camera/camera2/image_depth
Rear depth DDS topic: rt/camera/camera3/image_depth
Built-in quadruped robot obstacle avoidance enabled: True
Safety state machine started
```

## ROS 2 Topics

| Topic | Type | Description |
| --- | --- | --- |
| `/safety_guard/front/distance` | `std_msgs/Float32` | Front ROI distance |
| `/safety_guard/back/distance` | `std_msgs/Float32` | Rear ROI distance |
| `/safety_guard/state` | `std_msgs/String` | Current safety state |
| `/safety_guard/events` | `std_msgs/String` | Safety state transition event |
| `/safety_guard/depth_status` | `std_msgs/String` | Depth processing exception information |
| `/safety_guard/front/depth/image_raw` | `sensor_msgs/Image` | Forward depth image |
| `/safety_guard/back/depth/image_raw` | `sensor_msgs/Image` | Rear depth image |
| `/safety_guard/points` | `sensor_msgs/PointCloud2` | Combined front and rear ROI point cloud |
| `/safety_guard/markers` | `visualization_msgs/MarkerArray` | RViz distance markers |

Real-time sensor topics use `Best Effort + Keep Last(1)` QoS. The RViz configuration file is also set to Best Effort to avoid backpressure on safety distance publishing when visualization consumption is slow.

## RViz Display

Front and rear depth images and environmental point clouds:

![01](./assets/01.png)

Displayed content:

- `Front Depth Image`: forward depth image.
- `Back Depth Image`: rear depth image.
- `Safety ROI PointCloud`: combined front and rear ROI point cloud.
- `Obstacle Markers`: front and rear distance spheres and text labels.

Marker description:

- Green: the current distance is greater than the danger threshold.
- Red: the current distance is less than or equal to the danger threshold.
- `FRONT xx m`: distance calculated from the forward ROI.
- `BACK xx m`: distance calculated from the rear ROI.

The point cloud displays only the safety ROI area, not the full camera-view point cloud. This design highlights the obstacle avoidance trigger area and ensures real-time performance during long-term RViz operation.

When the obstacle distance is below the threshold, the Marker turns red as a warning ⚠️, and the console also displays the corresponding prompt.

## FAQ

### Depth Image Shows No Image in RViz

Check whether `depth_bridge_node` is running normally and confirm that the DDS network configuration is correct. If the console shows:

```text
can't open configuration file file:///xxx/cyclonedds.xml
Could not create DomainParticipant
```

It means the `CYCLONEDDS_URI` path is incorrect. Set it again:

```bash
unset CYCLONEDDS_URI
export CYCLONEDDS_URI=file:///home/dobot/dobot_safety_guard_demo/dobot_quad_sdk-main/cyclonedds.xml
```

### Cannot Connect to the Robot gRPC

Confirm that the development machine and quadruped robot are on the same wired subnet, and check whether the address is reachable:

```bash
ping 192.168.5.2
```

If the robot address is different, override it at startup:

```bash
ros2 launch dobot_safety_guard_demo safety_guard.launch.py grpc_addr:=<robot_ip>:50051
```

### Distance Is Displayed as nan

Possible causes:

- No depth image has been received.
- There are no valid depth points in the ROI area.
- The `min_valid_depth_m` or `max_valid_depth_m` filtering range is not suitable for the current scene.
- The DDS network or CycloneDDS network interface configuration is incorrect.

### RViz or Console Freezes After Restart

First confirm that no old processes remain:

```bash
pkill -f dobot_safety_guard_demo
pkill -f depth_bridge_node
pkill -f safety_guard_node
pkill -f rviz2
```

After reopening the terminal, follow the startup process again and run `source .venv/bin/activate`, `source /opt/ros/humble/setup.bash`, and `source install/setup.bash` in order.
